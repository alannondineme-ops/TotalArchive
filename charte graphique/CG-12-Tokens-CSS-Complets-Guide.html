02 — Structure fichiers

Organisation recommandée du projet

Structure modulaire pour faciliter la maintenance. Séparer les tokens globaux, les composants et les vues. Importer globals.css en premier dans chaque fichier.

Arborescence recommandée
src/ ├── styles/ │ ├── globals.css ← Tokens & reset (ce fichier) │ ├── components/ │ │ ├── buttons.css ← Styles boutons │ │ ├── inputs.css ← Styles formulaires │ │ ├── cards.css ← Styles cards │ │ ├── navigation.css ← Sidebar, topbar, tabs │ │ ├── modals.css ← Modals, dropdowns │ │ ├── toasts.css ← Toasts, alertes │ │ ├── tables.css ← Tables, pagination │ │ └── charts.css ← Graphiques │ └── views/ │ ├── dashboard.css ← Page dashboard │ ├── documents.css ← Page documents │ └── settings.css ← Page paramètres │ ├── components/ │ ├── Button.tsx │ ├── Input.tsx │ ├── Card.tsx │ └── ... │ └── app/ ├── layout.tsx ← Import globals.css ici ├── dashboard/ └── documents/
Import dans layout.tsx (Next.js / React)
// app/layout.tsx import '@/styles/globals.css'; import '@/styles/components/buttons.css'; import '@/styles/components/inputs.css'; // ... autres imports export default function RootLayout({ children }) { return ( <html lang="fr" data-theme="dark"> <body>{children}</body> </html> ); }
03 — Conventions de nommage

BEM simplifié & variables locales

Utiliser BEM simplifié pour les classes CSS. Variables locales préfixées par --_ pour scope composant. Noms descriptifs et cohérents.

Règles de nommage
Pattern Exemple Usage
.component .btn, .card, .modal Composant de base
.component--modifier .btn--primary, .btn--sm Variante du composant
.component__element .card__header, .card__body Élément enfant
.is-state .is-active, .is-loading État temporaire (JS)
--_local-var --_btn-bg, --_card-padding Variable locale au composant
Exemples de code
/* Bouton — BEM simplifié */ .btn { display: inline-flex; padding: 8px 14px; background: var(--bg-subtle); border: 1px solid var(--border-default); border-radius: var(--radius-sm); } .btn--primary { background: var(--accent-500); border-color: var(--accent-600); color: #fff; } .btn--sm { padding: 5px 10px; font-size: var(--text-sm); } .btn--lg { padding: 11px 20px; font-size: 15px; } .btn.is-loading { pointer-events: none; } /* Card — éléments enfants */ .card { background: var(--bg-elevated); border: 1px solid var(--border-subtle); border-radius: var(--radius-md); } .card__header { padding: var(--space-4) var(--space-5); border-bottom: 1px solid var(--border-subtle); } .card__body { padding: var(--space-5); } .card--glass { background: rgba(255,255,255,0.040); backdrop-filter: blur(14px); } /* Variables locales — scope composant */ .nav-item { --_nav-bg: transparent; --_nav-color: var(--text-tertiary); background: var(--_nav-bg); color: var(--_nav-color); } .nav-item.is-active { --_nav-bg: var(--accent-subtle-bg); --_nav-color: var(--accent-300); }
04 — Guide dark/light mode

Implémentation du thème clair

Le système utilise data-theme sur <html>. Toujours utiliser les tokens sémantiques (--bg-base, --text-primary) jamais les gris directs. Les couleurs accent restent identiques entre les deux modes.

Toggle thème — JavaScript
// Fonction toggle thème function toggleTheme() { const html = document.documentElement; const current = html.getAttribute('data-theme'); const next = current === 'light' ? 'dark' : 'light'; html.setAttribute('data-theme', next); localStorage.setItem('theme', next); } // Restaurer le thème au chargement const saved = localStorage.getItem('theme') || 'dark'; document.documentElement.setAttribute('data-theme', saved);
Règles dark/light mode
Toujours utiliser les tokens sémantiques : --bg-base, --text-primary, etc.
Ne jamais utiliser prefers-color-scheme directement — le toggle utilisateur prime
Les couleurs accent (--accent-*) restent identiques entre dark et light
Tester TOUS les composants dans les deux modes avant validation
INTERDIT : utiliser --gray-950 directement — toujours passer par --bg-base
05 — Checklist validation composant

14 points à vérifier avant validation

Checklist obligatoire avant de valider un nouveau composant. Cocher tous les points pour garantir la cohérence avec la charte graphique.

Grain appliqué — Opacity correcte selon type de surface (0.12 cards, 0.34 boutons)
Variables CSS — Toutes les valeurs passent par des tokens, jamais de hex en dur
Glassmorphisme — Uniquement sur sidebar/cards KPI/toasts, interdit ailleurs
Border-radius — Maximum 8px (--radius-lg), jamais ≥ 12px
Pas de dégradé — Sauf sous courbe graphique, interdit sur boutons/cards/fonds
DM Mono — Uniquement sur données techniques (refs, timestamps, hashes, labels UPPER)
Icônes Lucide SVG — Stroke 1.5px, taille 13-16px selon contexte
Focus ring visible — :focus-visible avec --shadow-focus
État disabled — opacity: 0.38 + aria-disabled="true"
Dark ET light mode testés — Composant fonctionnel dans les deux thèmes
Animations ≤ 250ms — Utiliser les 3 courbes autorisées uniquement
Prefers-reduced-motion — Respecté pour accessibilité
Contraste AA minimum — Ratio ≥ 4.5:1 pour texte normal vérifié
ARIA approprié — Attributs ARIA sur éléments interactifs si nécessaire
06 — Anti-patterns — 20 erreurs à éviter

Les erreurs les plus courantes

Liste exhaustive des erreurs à ne jamais commettre. Chaque anti-pattern est illustré avec la mauvaise pratique et la bonne solution.

1. Hex en dur vs Variables CSS
Mauvais
background: #63c8c1;
Impossible à maintenir, ne suit pas le thème
Correct
background: var(--accent-500);
Maintenable, suit automatiquement le thème
2. Glassmorphisme sur mauvais fond
Mauvais
Glassmorphisme sur --bg-base — pas de flou visible, effet perdu
Correct
Glassmorphisme uniquement sur --bg-base (sidebar, cards KPI, toasts)
3. Gradient sur bouton
Mauvais
background: linear-gradient(...);
Style consumer, pas institutionnel
Correct
background: var(--accent-500);
Couleur unie uniquement
4. DM Mono pour titre
Mauvais
font-family: var(--font-mono);
Sur titre ou texte courant — confusion typo
Correct
font-family: var(--font-sans);
Inter pour tout le contenu UI
5. Border-radius trop arrondi
Mauvais
border-radius: 12px; ou plus
Style consumer, pas institutionnel
Correct
border-radius: var(--radius-lg);
Maximum 8px — discret et professionnel
6. Font-size trop petite
Mauvais
font-size: 9px; ou moins
Illisible, WCAG fail
Correct
font-size: var(--text-xs);
Minimum 10px — lisible et accessible
7. Animation trop lente
Mauvais
transition: 400ms; ou plus
Interface perçue lente en usage intensif
Correct
transition: var(--dur-fast);
Maximum 250ms — réactivité perçue
8. Outline: none sans remplacement
Mauvais
outline: none; sans focus ring
Inaccessible au clavier
Correct
:focus-visible { box-shadow: var(--shadow-focus); }
Focus ring custom visible
9. Placeholder comme seul label
Mauvais
<input placeholder="Email">
Sans <label> — WCAG fail
Correct
<label for="email">Email</label>
Label visible + placeholder optionnel
10. Transition: all
Mauvais
transition: all 200ms;
Déclenche transitions non voulues + perf
Correct
transition: background-color 200ms, border-color 200ms;
Propriétés spécifiques uniquement
10 autres anti-patterns documentés
