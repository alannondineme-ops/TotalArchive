01 — Ratios de contraste WCAG

Conformité WCAG 2.1 niveau AA

Toutes les combinaisons texte/fond du système respectent le niveau AA minimum (4.5:1 pour texte normal, 3:1 pour texte large ≥18px). Les combinaisons atteignant le niveau AAA (7:1) sont indiquées. Obligatoire pour les administrations publiques.

Combinaisons principales — Mode sombre (défaut)
Texte Fond Ratio Niveau Usage
--text-primary (#F0F1F8) --bg-base (#0A0B0F) 14.8:1 AAA Titres, corps de texte principal
--text-secondary (#C2C5D6) --bg-panel (#10121A) 10.2:1 AAA Labels, sous-titres, navigation
--text-tertiary (#6B6F88) --bg-raised (#1A1D2B) 4.6:1 AA Texte secondaire, métadonnées
--accent-300 (#65D5C4) --bg-panel (#10121A) 8.9:1 AAA Liens, badges, éléments accent
#5DB882 (success) success-subtle 5.2:1 AA Messages de succès
#DC7070 (error) error-subtle 4.8:1 AA Messages d'erreur
#D4993A (warning) warning-subtle 5.5:1 AA Alertes, avertissements
#FFFFFF (blanc) --accent-500 (#179E8E) 4.9:1 AA Boutons primaires
Combinaisons principales — Mode clair
Texte Fond Ratio Niveau Usage
--text-primary (#10121A) --bg-base (#F8F9FC) 15.2:1 AAA Titres, corps de texte principal
--text-secondary (#3D4158) --bg-panel (#FFFFFF) 11.8:1 AAA Labels, sous-titres, navigation
--text-tertiary (#4D5068) --bg-raised (#E1E3EE) 6.1:1 AAA Texte secondaire, métadonnées
--accent-600 (#0E7E72) --bg-panel (#FFFFFF) 7.2:1 AAA Liens, éléments accent
Règles de contraste
Texte normal (≤18px) : ratio minimum 4.5:1 pour niveau AA, 7:1 pour AAA
Texte large (≥18px ou ≥14px gras) : ratio minimum 3:1 pour niveau AA, 4.5:1 pour AAA
Composants UI (bordures, icônes) : ratio minimum 3:1 avec l'arrière-plan adjacent
Texte sur fond coloré : toujours tester le ratio — ne jamais se fier à l'apparence visuelle seule
INTERDIT : text-placeholder (#4D5068) sur bg-base — ratio 3.8:1 insuffisant pour texte normal. Réservé aux placeholders uniquement.
02 — Focus visible

Focus ring — Indicateur de navigation clavier

Le focus ring est un double halo : 2px de la couleur de fond (--bg-base) + 4px accent-500. Obligatoire sur tous les éléments interactifs. Utilisez :focus-visible pour éviter l'affichage au clic souris sur les inputs.

Spécification CSS — Focus ring système
/* Token global — à utiliser partout */ --shadow-focus: 0 0 0 2px var(--bg-base), 0 0 0 4px var(--accent-500); /* Application sur éléments interactifs */ .btn:focus-visible, .card-clickable:focus-visible, .nav-item:focus-visible { outline: none; box-shadow: var(--shadow-focus); } /* Inputs : :focus-visible pour éviter focus au clic */ .form-input:focus-visible, .form-select:focus-visible { border-color: var(--accent-500); box-shadow: var(--shadow-focus); } /* Transition pour fluidité */ .btn, .input, .card { transition: box-shadow 150ms var(--ease-spring); }
Démonstration interactive — Appuyez sur Tab pour naviguer
Card cliquable avec focus
💡 Utilisez Tab pour naviguer entre les éléments et observer le focus ring
Focus ring sur fond coloré — Adapter le halo interne
/* Bouton danger : adapter le halo interne */ .btn-danger:focus-visible { outline: none; box-shadow: 0 0 0 2px var(--bg-base), 0 0 0 4px var(--error); } /* Nav item actif : halo interne accent-subtle-bg */ .nav-item--active:focus-visible { box-shadow: 0 0 0 2px var(--accent-subtle-bg), 0 0 0 4px var(--accent-500); }
Règles focus
Obligatoire sur tous les éléments interactifs : boutons, liens, inputs, cards cliquables, nav items
Utilisez :focus-visible au lieu de :focus pour éviter l'affichage au clic souris
Toujours inclure outline: none quand vous utilisez un focus ring custom
INTERDIT : outline: none sans focus ring de remplacement — rend l'interface inaccessible au clavier

03 — Navigation clavier

Ordre de tabulation & raccourcis

L'interface doit être entièrement navigable au clavier. Ordre logique : Topbar → Sidebar → Contenu principal. Skip link obligatoire. Trap focus dans les modals. Escape pour fermer.

Skip link — "Aller au contenu principal"
/* Skip link — invisible par défaut, visible au focus */ .skip-link { position: absolute; left: -9999px; top: 8px; z-index: 9999; background: var(--accent-500); color: #fff; padding: 8px 14px; border-radius: var(--radius-sm); font-family: var(--font-sans); font-size: var(--text-md); font-weight: 500; text-decoration: none; box-shadow: var(--shadow-lg); } .skip-link:focus { left: 8px; } /* HTML — placer en premier dans le body */ <a href="#main-content" class="skip-link">Aller au contenu principal</a> <main id="main-content">...</main>
Ordre de tabulation — App Shell
Ordre Zone Éléments Note
1 Skip link Lien "Aller au contenu principal" Visible uniquement au focus
2 Topbar Logo, recherche, notifications, profil De gauche à droite
3 Sidebar Navigation principale, items de menu De haut en bas
4 Contenu principal Titre, actions, tableau, formulaires Ordre logique de lecture
Trap focus dans les modals
/* JavaScript — trap focus dans modal */ function trapFocus(modal) { const focusable = modal.querySelectorAll( 'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])' ); const first = focusable[0]; const last = focusable[focusable.length - 1]; modal.addEventListener('keydown', (e) => { if (e.key === 'Tab') { if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus(); } else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus(); } } }); }
Raccourcis clavier
Touche Contexte Action
Tab Global Élément suivant
Shift + Tab Global Élément précédent
Enter / Space Bouton, lien Activer
Escape Modal, dropdown Fermer
↑ ↓ Dropdown, select Naviguer dans les options
Home / End Liste, tableau Premier / dernier élément
Règles navigation clavier
Skip link obligatoire en premier élément du <body>
Ordre de tabulation logique : suivre l'ordre visuel de lecture (gauche → droite, haut → bas)
Trap focus dans les modals — Tab ne doit pas sortir de la modal
Escape ferme les modals et dropdowns — restaurer le focus sur l'élément déclencheur
INTERDIT : tabindex positif (1, 2, 3...) — perturbe l'ordre naturel de navigation
04 — ARIA & Sémantique HTML

Attributs ARIA & structure sémantique

ARIA (Accessible Rich Internet Applications) enrichit la sémantique HTML pour les lecteurs d'écran. Règle d'or : HTML sémantique d'abord, ARIA uniquement quand nécessaire.

Attributs ARIA essentiels
Attribut Usage Exemple
aria-label Label pour éléments sans texte visible <button aria-label="Fermer"><svg>...</svg></button>
aria-labelledby Référence un élément comme label <div role="dialog" aria-labelledby="modal-title">
aria-describedby Référence une description ou aide <input aria-describedby="error-msg">
aria-hidden Masque du contenu décoratif <svg aria-hidden="true">...</svg>
aria-live Zone de mise à jour dynamique <div aria-live="polite">Document enregistré</div>
aria-current Élément actif dans navigation <a aria-current="page">Accueil</a>
aria-expanded État ouvert/fermé d'un élément <button aria-expanded="false">Menu</button>
aria-selected Élément sélectionné (tabs, liste) <div role="tab" aria-selected="true">
aria-disabled Élément désactivé <button aria-disabled="true">Enregistrer</button>
Rôles ARIA pour composants UI
Composant Rôle Attributs associés
Toast info/success role="status" aria-live="polite"
Toast error role="alert" aria-live="assertive"
Modal role="dialog" aria-labelledby, aria-modal="true"
Tabs container role="tablist" —
Tab item role="tab" aria-selected, aria-controls
Tab panel role="tabpanel" aria-labelledby
Dropdown menu role="menu" aria-labelledby
Dropdown item role="menuitem" —
Graphique Canvas role="img" aria-label="Description du graphique"
Exemples de code
/* Bouton icon-only — aria-label obligatoire */ <button class="btn btn-icon" aria-label="Actualiser la page"> <svg aria-hidden="true">...</svg> </button> /* Input avec erreur — aria-describedby */ <label for="email">Email</label> <input id="email" type="email" aria-describedby="email-error"> <span id="email-error" class="form-error-msg">Format invalide</span> /* Breadcrumb — aria-current sur dernier élément */ <nav aria-label="Fil d'Ariane"> <a href="/accueil">Accueil</a> <a href="/documents">Documents</a> <a href="/documents/123" aria-current="page">ARC-2024-00847</a> </nav> /* Sidebar collapse — aria-expanded */ <button aria-expanded="true" aria-label="Réduire la navigation"> <svg aria-hidden="true">...</svg> </button> /* Graphique Canvas — role="img" + aria-label */ <canvas role="img" aria-label="Graphique : Évolution des versements 2024, 847 documents en janvier, 1203 en février"></canvas>
Règles ARIA
HTML sémantique d'abord : utilisez <button>, <nav>, <main> plutôt que des <div> avec rôles ARIA
aria-label obligatoire sur tous les boutons icon-only
aria-hidden="true" sur toutes les icônes décoratives et le grain SVG
Champs de formulaire : toujours associer <label> via for/id
INTERDIT : placeholder comme seul label de champ — invisible pour les lecteurs d'écran une fois rempli
INTERDIT : aria-hidden="true" sur du contenu informatif — le rend invisible aux lecteurs d'écran
05 — Touch targets

Tailles minimales de zones cliquables

WCAG 2.5.5 niveau AAA recommande 44×44px minimum pour les zones cliquables. Obligatoire pour les interfaces tactiles. Les boutons icon-only doivent avoir un padding suffisant même si l'icône est petite.

Spécifications touch targets
Élément Taille minimale Implémentation
Bouton standard ≥ 44×44px padding: 8px 14px (36px hauteur) — acceptable pour desktop
Bouton icon-only ≥ 44×44px padding: 15px pour icône 14px → 44px total
Nav item sidebar ≥ 40×40px padding: 8px 12px + min-height: 40px
Checkbox / Radio ≥ 24×24px width: 16px; height: 16px + padding parent
Toggle switch ≥ 36×20px width: 36px; height: 20px
Lien dans texte Exempt Pas de minimum requis (WCAG 2.5.5 exception)
Exemple — Bouton icon-only accessible
/* Bouton icon-only — padding pour atteindre 44px */ .btn-icon { display: inline-flex; align-items: center; justify-content: center; padding: 15px; /* 15px × 2 + 14px icône = 44px */ background: var(--bg-raised); border: 1px solid var(--border-default); border-radius: var(--radius-sm); cursor: pointer; } .btn-icon svg { width: 14px; height: 14px; }
Règles touch targets
Minimum 44×44px pour interfaces tactiles (mobile, tablette)
Desktop : 36×36px acceptable si usage clavier/souris uniquement
Espacement minimum 8px entre zones cliquables adjacentes
INTERDIT : boutons < 32×32px sur interfaces tactiles — trop difficiles à cliquer
06 — États accessibles

États disabled, erreur, loading

Les états doivent être communiqués visuellement ET aux technologies d'assistance. Ne jamais se fier uniquement à la couleur pour indiquer un état.

État disabled
/* Disabled — visuel + ARIA + cursor */ .btn:disabled, .btn[aria-disabled="true"] { opacity: 0.38; cursor: not-allowed; pointer-events: none; } /* HTML — utiliser disabled natif quand possible */ <button disabled>Enregistrer</button> /* Si disabled natif impossible (div, span) */ <div role="button" aria-disabled="true">Action</div>
Erreurs de formulaire
/* Erreur — couleur + icône + message lié */ <div class="form-field has-error"> <label for="email">Email</label> <input id="email" type="email" class="form-input" aria-invalid="true" aria-describedby="email-error" > <span id="email-error" class="form-error-msg"> <svg aria-hidden="true">...</svg> Format invalide </span> </div> /* CSS — bordure + fond coloré */ .form-field.has-error .form-input { border-color: var(--error); background: var(--error-subtle); }
Tableaux accessibles
/* Tableau — scope sur th */ <table> <thead> <tr> <th scope="col">Référence</th> <th scope="col">Titre</th> <th scope="col">Date</th> </tr> </thead> <tbody> <tr> <td>ARC-2024-00847</td> <td>Délibération conseil</td> <td>15/01/2024</td> </tr> </tbody> </table>
Règles états accessibles
Ne jamais utiliser la couleur seule pour indiquer un état — toujours ajouter icône ou texte
Erreurs de formulaire : aria-invalid="true" + aria-describedby vers message d'erreur
Images : alt descriptif ou alt="" si purement décorative
Tableaux : <th scope="col"> pour les en-têtes de colonnes
07 — RGAA 4.1

Référentiel Général d'Amélioration de l'Accessibilité

Le RGAA 4.1 est le référentiel français obligatoire pour les administrations publiques. Basé sur WCAG 2.1, il impose le niveau AA minimum. 106 critères répartis en 13 thématiques.

Thématiques RGAA 4.1
Thématique Critères Points clés pour ce système
1. Images 8 critères Attribut alt, images décoratives, images porteuses d'information
3. Couleurs 4 critères Contraste AA minimum, information non portée par la couleur seule
7. Scripts 5 critères Composants JS accessibles, gestion focus, ARIA
8. Éléments obligatoires 10 critères Doctype, lang, title, structure HTML5
10. Présentation 14 critères CSS pour mise en forme, pas de tableaux de mise en page
11. Formulaires 13 critères Labels associés, messages d'erreur, aide à la saisie
12. Navigation 14 critères Skip links, fil d'Ariane, navigation cohérente, focus visible
13. Consultation 12 critères Pas de limite de temps, contrôle animations, téléchargements
Checklist RGAA — 20 critères essentiels
1.1 — Toutes les images ont un attribut alt (vide si décorative)
3.1 — Information non portée par la couleur seule (icône + texte pour erreurs)
3.2 — Contraste texte/fond ≥ 4.5:1 (AA) pour texte normal
7.1 — Composants JS accessibles au clavier (focus, Tab, Enter/Space)
7.3 — Scripts n'empêchent pas la navigation clavier
8.2 — Code HTML valide (pas d'erreurs critiques)
8.9 — Balises utilisées à des fins de présentation (structure sémantique)
10.7 — Focus visible sur tous les éléments interactifs
11.1 — Chaque champ de formulaire a une étiquette (<label>)
11.10 — Messages d'erreur de saisie explicites et liés au champ (aria-describedby)
12.1 — Liens d'évitement (skip links) présents
12.2 — Fil d'Ariane présent sur toutes les pages (sauf accueil)
12.7 — Ordre de tabulation cohérent et logique
12.8 — Navigation cohérente sur toutes les pages
13.1 — Pas de limite de temps (ou possibilité de prolonger)
13.8 — Contenu en mouvement contrôlable (pause, stop)
Niveau de conformité requis
Obligation légale pour les administrations publiques
Les sites web et applications des administrations publiques doivent respecter les normes d'accessibilité WCAG 2.1 niveau AA minimum. Déclaration d'accessibilité obligatoire.
